本示例中将构建一个包含两个简单工具的 mcp server: `get_alerts` 和 `get_forecast`，然后使用基础部分构建的 agent 连接到这个 server.

## MCP 核心概念
MCP Server 可以提供以下三种主要的能力：
- Resources: 可以被 Client 获取的只读数据，如 API 响应或文件内容。
- Tools: 可以被 Agent Client 调用的工具，需要经过批准或认证。
- Prompts: 预先编写的提示词模板，帮助用户完成特定任务。


## 关于日志
在构建 MCP Server 时，需要谨慎处理日志：
- 对于 `STDIO-based` 的 Server: 不要将日志写入 `stdout`，这会损坏 `JSON-RPC` 消息并导致服务器崩溃，如 `python` 的 print() 函数默认写入 stdout，所以不要把它写入 STDIO Server中。
- 对于 `HTTP-based` 的 Server: 可以使用 print 进行输出，因为这不会干扰 HTTP 的响应。

<Note>
**Stdio-based**
- 客户端把服务器作为**子进程**启动，双方通过本机进程的标准输入/输出流通信（JSON-RPC 消息换行分隔）。
- 只适用于**同一台机器上的本地进程通信**，没有网络开销，性能最优。

**Streamable HTTP-based**
- 使用 **HTTP POST** 传递客户端到服务器的消息，并可用 **Server-Sent Events** 实现流式响应。
- 支持**远程服务器通信**，并支持标准 HTTP 认证方式（Bearer token、API key、自定义 headers，推荐 OAuth）。
</Note>


### 最佳实践
- 使用标准 `logging` 模块，其写入 `stderr`。
- 每个模块创建一个 `logger`，并在工具中调用它，格式形如 `logging.getLogger(__name__)`

```python
import logging

logger = logging.getLogger(__name__)

# ❌ Bad (STDIO)
print("Processing request")

# ✅ Good (STDIO)
logger.info("Processing request")  # writes to stderr
```


## Start Building

从以下内容开始，完整版在 [mcp_server.py](https://github.com/kongds1999/agent_from_scratch/blob/main/mcp_server.py)

```python
from typing import Any

import httpx2
from mcp.server import MCPServer

# Initialize MCPServer
mcp = MCPServer("weather")

# Constants
NWS_API_BASE = "https://api.weather.gov"
USER_AGENT = "weather-app/1.0"
```

httpx2 是 SDK 本身所依赖的 HTTP 客户端，因此安装 mcp 时会自动引入。

```python
async def make_nws_request(url: str) -> dict[str, Any] | None:
    """Make a request to the NWS API with proper error handling."""
    headers = {"User-Agent": USER_AGENT, "Accept": "application/geo+json"}
    async with httpx2.AsyncClient() as client:
        try:
            response = await client.get(url, headers=headers, timeout=30.0)
            response.raise_for_status()
            return response.json()
        except Exception:
            return None


def format_alert(feature: dict) -> str:
    """Format an alert feature into a readable string."""
    props = feature["properties"]
    return f"""
Event: {props.get("event", "Unknown")}
Area: {props.get("areaDesc", "Unknown")}
Severity: {props.get("severity", "Unknown")}
Description: {props.get("description", "No description available")}
Instructions: {props.get("instruction", "No specific instructions provided")}
"""
```

以上一些必要的辅助函数或处理，用于从国家气象服务 API 中查询和格式化数据。

### 工具执行
```python
@mcp.tool()
async def get_alerts(state: str) -> str:
    """Get weather alerts for a US state.

    Args:
        state: Two-letter US state code (e.g. CA, NY)
    """
    url = f"{NWS_API_BASE}/alerts/active/area/{state}"
    data = await make_nws_request(url)

    if not data or "features" not in data:
        return "Unable to fetch alerts or no alerts found."

    if not data["features"]:
        return "No active alerts for this state."

    alerts = [format_alert(feature) for feature in data["features"]]
    return "\n---\n".join(alerts)


@mcp.tool()
async def get_forecast(latitude: float, longitude: float) -> str:
    """Get weather forecast for a location.

    Args:
        latitude: Latitude of the location
        longitude: Longitude of the location
    """
    # First get the forecast grid endpoint
    points_url = f"{NWS_API_BASE}/points/{latitude},{longitude}"
    points_data = await make_nws_request(points_url)

    if not points_data:
        return "Unable to fetch forecast data for this location."

    # Get the forecast URL from the points response
    forecast_url = points_data["properties"]["forecast"]
    forecast_data = await make_nws_request(forecast_url)

    if not forecast_data:
        return "Unable to fetch detailed forecast."

    # Format the periods into a readable forecast
    periods = forecast_data["properties"]["periods"]
    forecasts = []
    for period in periods[:5]:  # Only show next 5 periods
        forecast = f"""
{period["name"]}:
Temperature: {period["temperature"]}°{period["temperatureUnit"]}
Wind: {period["windSpeed"]} {period["windDirection"]}
Forecast: {period["detailedForecast"]}
"""
        forecasts.append(forecast)

    return "\n---\n".join(forecasts)
```

`@mcp.tool()`装饰器轻松将一个函数注册为一个标准的 `mcp tool`，函数签名下的```"""```注释行是针对该工具暴露的 `description`以及参数说明，Agent Client 使用渐进式加载工具列表时可以看到这些描述。

### Running the server
如果是使用 [uv](https://docs.astral.sh/uv/getting-started/installation/) 来构建，可以使用 `uv run mcp_server.py` 来启动服务器。
```python
if __name__ == "__main__":
    mcp.run(transport="stdio")
```

<Info>
注意，当前启动方式设置为 transport="stdio"，启动后会一直等待 stdin 上的 JSON-RPC 消息，不会主动打印任何内容，所以终端看起来是空白卡住的。
</Info>

## 使用 agents SDK 集成

在完成服务端的构建后，下一步就是使用 **OpenAI Agents SDK** 连接到这个 MCP Server。

OpenAI Agents SDK 提供了原生的 MCP 客户端支持（位于 `agents.mcp`），支持四种接入模式：
1. **`MCPServerStdio`**：本地子进程模式，通过标准输入/输出流（STDIO）进行 JSON-RPC 通信。
2. **`MCPServerStreamableHttp`**：流式 HTTP 模式，适用于远程自托管 MCP 服务。
3. **`MCPServerSse`**：基于 Server-Sent Events 的 HTTP 传输模式。
4. **`HostedMCPTool`**：由 OpenAI 托管的 MCP 工具（配合 Responses API 使用）。

由于前面我们编写的 `mcp_server.py` 是以 `stdio` 传输模式运行的本地进程，因此我们选用 **`MCPServerStdio`** 进行集成。

### 核心工作原理

使用 `MCPServerStdio` 时，Agents SDK 会承担以下底层通信与生命周期工作：

- **子进程托管**：通过异步上下文管理器（`async with MCPServerStdio(...) as server:`）自动启动 `mcp_server.py` 进程，并在退出时自动关闭管道、清理子进程。
- **协议握手与工具发现**：客户端通过 JSON-RPC 发送初始化请求并协商协议版本，自动调用 `tools/list` 提取服务端注册的工具（如 `get_alerts` 与 `get_forecast`）及其 JSON Schema 参数说明。
- **透明工具路由**：当大模型决定调用 MCP 工具时，SDK 拦截模型生成的函数调用请求，将其封装为 MCP `tools/call` 请求下发给子进程，等待服务端计算完毕后，再将工具执行结果格式化回传给大模型。

整个过程开发者**无需手动编写任何工具包装函数（FunctionTool）**，只需将 server 挂载到 Agent 的 `mcp_servers` 列表中即可。

### 实现 Client 代码

以下是连接 MCP Server 的完整 Agent Client 实现，代码具体保存在 `src/mcp_client.py` 中：

```python
import asyncio
import os
import sys
from pathlib import Path
from dotenv import load_dotenv
from agents import Agent, Runner, set_tracing_disabled, set_default_openai_api
from agents.mcp import MCPServerStdio

# 加载环境变量并配置 SDK
load_dotenv()
set_tracing_disabled(True)  # 禁用 tracing 获取干净的控制台输出
set_default_openai_api("chat_completions")  # 兼容 LiteLLM / 第三方代理服务

# 定位同目录下的 MCP Server 脚本
SERVER_SCRIPT = Path(__file__).parent / "mcp_server.py"


async def main():
    print("\033[90m openai-agents-mcp-client v0.1.0 \033[0m")

    # 1. 配置 Stdio 模式的 MCP Server
    # Agents SDK 会负责启动子进程、维持 stdin/stdout 双向 JSON-RPC 通信，并在退出时自动关闭
    async with MCPServerStdio(
        name="WeatherServer",
        params={
            "command": sys.executable,
            "args": [str(SERVER_SCRIPT)],
        },
        cache_tools_list=True,  # 缓存工具列表，减少每轮重复枚举工具的开销
    ) as server:
        # 2. 将 MCP Server 挂载到 Agent
        # Agent 初始化时会自动调用 tools/list 发现 get_alerts 和 get_forecast 工具
        agent = Agent(
            name="WeatherAssistant",
            model="openai/gpt-5.5",
            instructions=(
                "You are a helpful weather assistant. "
                "Use the provided weather MCP tools (get_alerts, get_forecast) to answer questions "
                "about weather alerts and forecasts accurately."
            ),
            mcp_servers=[server],
        )

        # 3. 存储多轮会话历史
        conversation_history = []

        print("\033[36mConnected to Weather MCP Server. Type 'exit' to quit.\033[0m\n")

        # 4. 终端交互 REPL
        while True:
            try:
                query = input("\033[32m> \033[0m").strip()
            except (EOFError, KeyboardInterrupt):
                print("\n\033[31mExiting...\033[0m")
                break

            if not query or query.lower() in {"q", "exit", "quit"}:
                print("\033[31mExiting REPL.\033[0m")
                break

            # 将新输入加入历史会话
            current_input = conversation_history + [{"role": "user", "content": query}]

            try:
                # Runner 自动进行 ReAct 循环，执行 MCP 工具并聚合结果
                result = await Runner.run(agent, input=current_input)
                conversation_history = result.to_input_list()

                print("\n\033[32mFinal Answer:\033[0m")
                print(result.final_output)
                print()
            except Exception as e:
                print(f"\n\033[31mError during execution: {e}\033[0m\n")


if __name__ == "__main__":
    asyncio.run(main())
```

### 进阶：配置与最佳实践

<Note>
**1. 工具缓存 (`cache_tools_list`)**
默认情况下，Agent 每次运行（`Runner.run`）都会重新向所有 MCP Server 发起 `tools/list` 探测。如果 MCP Server 的工具集合是固定的，建议在初始化时传入 `cache_tools_list=True`，避免重复请求带来的延迟。若需刷新缓存，可调用 `server.invalidate_tools_cache()`。

**2. 避免工具重名冲突 (`include_server_in_tool_names`)**
当挂载多个 MCP Server 时，不同服务可能提供同名工具。可以通过 Agent 级别的 `mcp_config` 配置前缀：
```python
agent = Agent(
    name="WeatherAssistant",
    mcp_servers=[server],
    mcp_config={
        "include_server_in_tool_names": True,  # 暴露给模型的工具名会自动加上服务器前缀
    },
)
```

**3. 工具筛选 (`tool_filter`)**
如果 MCP Server 暴露了非常多的工具，但当前 Agent 只需要其中几个，可以使用 `create_static_tool_filter` 过滤工具，减少模型上下文中的 Prompt 消耗：
```python
from agents.mcp import create_static_tool_filter

server = MCPServerStdio(
    params={"command": sys.executable, "args": [str(SERVER_SCRIPT)]},
    tool_filter=create_static_tool_filter(allowed_tool_names=["get_forecast"]),
)
```
</Note>
