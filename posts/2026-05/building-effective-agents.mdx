<Note>
一个成功设计的 Agent 往往源于简单、可组合的模式，而非复杂的框架。
</Note>
### 1. 核心定义：工作流 vs. 智能体
- **工作流 (Workflows)：** 通过预定义的代码路径编排 LLM 和工具。
- **智能体 (Agents)：** LLM 动态地指导自己的流程和工具使用，对任务执行拥有自主控制权。
### 2. 五大核心设计模式
文章提出了从简单到复杂的五种构建块和工作流模式：
- **增强型 LLM (Augmented LLM)：** 最基本的构建块，为 LLM 配备检索（Retrieval）、工具（Tools）和记忆能力。
![](/images/posts/building-effective-agents/e74f344424.png)
- **提示链 (Prompt Chaining)：** 将任务分解为一系列步骤，每一步处理上一步的输出。适用于固定子任务的场景。
![](/images/posts/building-effective-agents/6fbb91d5fb.png)
- **路由 (Routing)：** 将输入分类并导向专门的后续任务。适用于需要分离关注点、优化性能和成本的情况。
![](/images/posts/building-effective-agents/cd7aa6600b.png)
- **并行化 (Parallelization)：** LLM 同时处理子任务。包括**分段（Sectioning）**（如同时进行响应生成和内容审查）和**投票（Voting）**（多次运行取最优）。
![](/images/posts/building-effective-agents/0686eedbe4.png)
- **调度者-执行者 (Orchestrator-Workers)：** 中心 LLM 动态分解任务并分配给工作者 LLM，最后汇总结果。适用于子任务不可预测的复杂任务（如代码重构）。
![](/images/posts/building-effective-agents/8772ba00b6.png)
- **评估者-优化者 (Evaluator-Optimizer)：** 一个调用生成响应，另一个提供反馈并循环优化。适用于有清晰评估标准且迭代能显著提升质量的场景。
![](/images/posts/building-effective-agents/2ae178d0a9.png)
### 3. 构建建议与原则
- **保持简单：** 优先选择最简单的解决方案，只有在必要时才增加复杂性。
- **透明度：** 显式展示 Agent 的规划步骤，使其行为可预测、易调试。
- **精心设计 ACI（Agent-Computer Interface）：** 像对待人类接口（HCI）一样对待工具设计。
	- **提供清晰的工具文档和示例。**
	- 使用模型熟悉的格式。
	- 测试并迭代工具的参数命名和描述，例如使用绝对路径而非相对路径以减少错误。
---
**总结一句话：** 别盲目追求复杂的 Agent 架构，从简单的提示链和工具调用开始，通过衡量性能逐步迭代。
